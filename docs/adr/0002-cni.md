# 0002: Keep kind's default CNI (kindnet) for NetworkPolicy

- **Status:** accepted
- **Date:** 2026-10-26

## Context

Phase 4 relies on NetworkPolicy: default-deny plus explicit allows. A NetworkPolicy object is only data. The CNI plugin enforces it, and a CNI that ignores it accepts the objects and silently lets all traffic through. For years, kind's default CNI (kindnet) did exactly that, which is why "install Calico on kind" is common advice.

## Decision

Keep kindnet. Since kind v0.24.0 it enforces NetworkPolicy through [kube-network-policies](https://github.com/kubernetes-sigs/kube-network-policies). This repo pins kind v0.33.0 (node image `kindest/node:v1.37.0`, kindnet `kindnetd:v20260820-69b56db7`).

**Evidence (2026-10-26, this pin):** a busybox server pod on `secure-k8s-worker` and a client pod on `secure-k8s-worker2`. Before any policy the client reached the server; after a default-deny-ingress policy in that namespace, the same request timed out. Phase 4's `tests/security/test_netpol.sh` is the permanent proof and must fail loudly if enforcement ever stops (e.g. after a kind upgrade).

## Alternatives considered

- **Calico (`disableDefaultCNI: true`):** a widely used production CNI with extra policy CRDs (GlobalNetworkPolicy, policy tiers) and flow logs. But it adds an operator and several images to pin, mirror (Phase 8) and keep updated, plus another component in the cluster that must be trusted. This project only uses standard `networking.k8s.io/v1` NetworkPolicy, which kindnet covers.
- **Cilium:** eBPF-based, with L7 and DNS-aware (FQDN) policies. Powerful, but heavier to run on kind and unnecessary for standard policies.

## Consequences

- Fewer moving parts: kindnet ships inside the node image, so no extra images to pull or mirror.
- Only standard NetworkPolicy. Egress can be restricted by IP/CIDR and port, not by domain name. Cluster-wide, admin-level policies would need a different CNI.
- Enforcement depends on the kind version: a kind upgrade requires re-running the Phase 4 tests.
- In production the CNI comes with the managed cluster (or is chosen with the platform). The policies themselves stay portable because they use the standard API.
