# 0004: Package the app as a Helm chart

- **Status:** accepted
- **Date:** 2026-10-26

## Context

The app's manifests (Deployment, Service, ServiceAccount, ConfigMap) must take a few environment-specific inputs: the image registry (the local registry now, a mirror in Phase 8), a digest that changes with every build, and later other values. The same rendered output has to be tested in CI against the Kyverno policies that run in the cluster, and in an air-gapped environment it has to be installable from a file.

## Decision

A Helm chart in `charts/app`, installed with `helm upgrade --install` (Helm v4.3.1, pinned).

- `values.schema.json` rejects missing or malformed digests and the tag `latest` at lint, template and install time, before anything reaches the cluster.
- `ci/lint-values.yaml` supplies a placeholder digest, so the chart renders without a registry (`make lint`, CI).
- `make deploy` passes the registry and the digest read back from the registry, and waits for the rollout (`--wait=watcher`, because Helm 4 does not wait by default).

## Alternatives considered

- **Kustomize:** no templating language, only patches over plain YAML, which is easier to read and review. But every value has to be expressed as a patch or a replacement, there is no input validation like a values schema, and there is no packaged, versioned artifact or release history to roll back to.
- **Plain manifests plus `sed`/`envsubst`:** no validation, no release tracking. Fine for one-off demos, fragile beyond that.

## Consequences

- `helm package` produces a versioned `.tgz` that can be mirrored and installed offline (Phase 8).
- Helm keeps release history as Secrets in the release namespace (`sh.helm.release.v1.<name>.v<rev>`, verified on v4.3.1), so `helm rollback` works. The deployer therefore needs Secret access in `app` (Phase 6). Anything passed as a value is stored in that history, which is why the app secret is not a chart value (ADR 0005).
- Templates add an indirection: reviewers should read `helm template` output, not only the templates. CI tests that rendered output.
- Each `make deploy` after a rebuild rolls the pods, even without code changes, because the index digest changes (ADR 0003).
